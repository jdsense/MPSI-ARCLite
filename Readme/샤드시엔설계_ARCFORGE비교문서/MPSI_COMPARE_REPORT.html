0. 먼저 읽을 요약

0.1 결론

  1. 화면의 뼈대(메뉴 5축, 0~13단계, 매트릭스 팝업)는 설계를 잘 따르고 있다. 프로젝트 관리대장, 원청사 견적, 금형 견적~PPAP까지 9개 화면이 모두 존재하고 제목, 안내 배너, 검색 조건의 큰 틀이 맞다.
  2. 가장 큰 차이는 "자동 채움"이다. 설계에서는 프로젝트를 고르는 즉시 원청사, 프로젝트명, 제품명 등이 읽기 전용 칸에 채워지고 신규 번호도 미리 보인다. 컨버전 사이트는 프로젝트 번호 연동, 원청사 견적, 금형 견적 등록 팝업 세 곳 모두에서 선택해도 아무것도 채워지지 않았다. 프로젝트를 선택하는 모달 10곳을 모두 점검한 결과(3.4절), 선택 후 저장된 정보를 불러오는 기능이 동작하는 곳은 한 곳도 없었다. 행을 선택해서 여는 팝업만 값이 채워진다.
  3. 원인은 구현 위치의 차이로 보인다. README에 따르면 채번과 자동 보완은 화면이 아니라 저장 프로시저(PROC_PROJECTMASTER_SAVE, PROC_C110000_Save)가 저장할 때 수행한다. 설계는 선택하는 순간 화면에서 보여 주는 방식이다. 화면 쪽 조회 연결을 추가하면 설계에 맞출 수 있다.
  4. 상세 조작 방식이 다르다. 설계는 행마다 상세/심의 버튼을 누르는 방식이고, 컨버전 사이트는 행을 체크한 뒤 상단 툴바 버튼을 누르는 방식이다. 상세 팝업도 설계는 읽기와 판정용 카드, 컨버전은 저장 버튼이 있는 편집 폼과 편집 그리드이다.
  5. 빠진 것과 더해진 것이 있다. 배송현황 메뉴가 보이지 않고, 기준정보 6개 화면과 시스템관리가 더해졌다. 등록 팝업의 입력 항목은 화면마다 설계보다 줄거나 달라졌다.
  6. 배송현황은 문서상 본사 필수 메뉴다. 권한설정, 엔드유저 가이드, 배송 API 명세 세 문서가 모두 본사(MPSI) 메뉴로 정의하는데 컨버전 사이트에는 없다. 단순 누락일 가능성이 높다.
  7. 자동 채움 시점은 문서에도 "저장 시"로 적혀 있다. 엔드유저 가이드가 저장 시 채번과 보완을 정의하고 있어서, 컨버전 사이트는 가이드대로 만들어진 것이다. 설계 목업(선택 시 즉시 채움)과 가이드(저장 시 채움)가 서로 다르므로 어느 쪽을 기준으로 삼을지 먼저 결정해야 한다(8절).
  8. 저장소 DDL과 설계서는 라이브 DB보다 오래된 버전이다. 99개 테이블 기준이고 ProjectMaster에 OfficialProjectID 등이 없다. 라이브(112개)와 맞춘 갱신본이 필요하다(8.2절).
  9. 행을 선택해야 켜지는 버튼과 팝업을 모두 열어 다시 확인했다(4.12절). 이전 비교에서 빠졌던 부분이다. 팝업 대부분은 설계의 판정 카드가 아니라 저장 버튼이 있는 편집 폼과 편집 그리드다.
  10. 선택한 행과 연결되지 않고 빈 폼으로 열리는 팝업이 7개 있다. 제품검토 승인, 금형 설계 승인, 금형 발주서(C220000), 상세조회(C230000), 금형 이관, 금형제작 승인서(C240000). 행을 선택해도 값이 비어 있다. 반면 업무 이력 메모, 첨부 파일, 이관 5대 서류, 견적 상세·업체·자료 팝업은 선택 행의 값으로 열린다.
  11. 설계의 판정 버튼(승인·반려, 검토 완료, Pass/Fail, 수주 확정)이 어느 팝업에도 보이지 않는다. 승인 상태는 true/false 값이나 상태 선택 상자로 표시되고, PPAP는 승인 후 PO 번호를 입력 칸에 직접 적는 형태다.

0.3 근거 표시

관찰 컨버전 사이트에서 직접 조작해 확인한 사실. README ACRFORGE README.md에 적힌 내용. 추정 관찰과 README를 연결한 해석. 구현 담당자 확인이 필요하다. 미확인 이번에 확인하지 못한 부분.

저장, 승인, 발송, 삭제 같은 실행 버튼은 컨버전 사이트에서도 누르지 않았다. 데이터가 바뀌지 않도록 화면을 열고 선택 상자를 바꿔 보는 것까지만 했다. 따라서 "저장 시 어떻게 되는가"는 README의 설명을 근거로 한 추정이다.

1.2 확인한 화면과 못한 화면

  • 확인함: 9개 화면의 목록과 검색 조건, 프로젝트 등록·수정 팝업, 매트릭스·상세 공정 팝업, 원청사 견적(등록, 상세, 부품 단가, 파일 이력, 메모), 금형 견적 등록, 양산 견적 등록의 구성. 행을 선택해야 켜지는 툴바 버튼과 행 안 버튼은 C100000~C330000의 모든 화면에서 열어 확인했다(4.12절).
  • 미확인 기준정보 6개 화면의 상세 동작과 시스템관리 하위 메뉴(펼쳐지지 않음). 양산 견적 등록에서 프로젝트를 선택했을 때의 동작. 모든 저장·삭제·판정 버튼의 실제 결과. 팝업 안에서 스크롤해야 보이는 아래쪽 일부(C210000 상세/심의, C240000 금형제작 승인서 등).
  • 컨버전 사이트의 목록 그리드는 화면에 그려지는 형태라 글자로 읽을 수 없어 스크린샷으로 확인했다. 그래서 열 이름이 잘린 곳이 있다.

3.4 모든 모달의 "프로젝트 선택 시 저장된 정보 불러오기" 점검

4.12 행을 선택해야 켜지는 버튼과 팝업 (재검토)

이전 비교에서는 목록과 등록 팝업 위주로 봤고, 목록의 행을 선택해야 켜지는 상단 버튼과 행 안의 버튼은 대부분 열어 보지 않았다. 이번에 모든 화면에서 직접 눌러 확인했다. 저장, 삭제, 승인, 다운로드는 누르지 않았다.

조작 규칙 관찰 - 행의 데이터 칸(번호 등)을 누르면 행이 강조되고 툴바 버튼이 켜진다. 맨 앞 선택 칸만 눌러서는 선택으로 인식되지 않는 경우가 있었다(C100000에서 [수정]이 "먼저 선택하세요" 경고를 띄움). - 이번 마지막 접속에서는 C220000 첫 화면의 기본 조회 기간이 "전체"가 아니라 "오늘"(2026-11-02)로 설정돼 0건(No data found)이 나왔다. 접속 날짜가 바뀐 뒤 처음 열었을 때의 동작으로 보이며, 다른 날에는 "전체"로 열렸다. 기본 기간 규칙 확인이 필요하다. 관찰 - 선택 없이 툴바 버튼을 누르면 브라우저 경고창이 뜬다. 예: "수정할 프로젝트를 먼저 목록에서 선택하세요." 팝업이 아니라 경고창이라 확인을 눌러야 화면이 풀린다. - 팝업은 대부분 "편집 폼 또는 편집 그리드 + 저장 / 삭제 / 닫기" 구성이다. 설계의 판정 중심 카드와 다르다. - 더블클릭 관찰 C100000에서는 행의 제품명 칸을 더블클릭하면 프로젝트 상세 공정 팝업이 열린다(해당 행의 프로젝트로 열림). 프로젝트 번호 칸 더블클릭은 변화가 없었다. C110000, C210000, C220000, C240000에서는 제품명 칸을 더블클릭하면 모달이 아니라 셀 편집 상태(흰 입력 상자)로 바뀌고, C220000과 C230000의 번호 칸 더블클릭은 변화가 없었다. 설계는 프로젝트 번호 링크를 눌러 상세 공정 팝업을 여는 방식이므로 열리는 위치가 다르다.

8.5 기준 결정표

설계 목업과 가이드가 서로 다른 곳은 아래와 같다. "목업 기준"을 선택하면 화면 수정이 필요하고, "가이드 기준"을 선택하면 목업 명세를 고쳐야 한다.

# 쟁점 목업 가이드 / 라이브 제안
1 자동 채움 시점 선택 즉시 화면에 채움 저장 시 서버가 채움 목업 기준(저장 전에 확인·수정 가능). 서버 보완은 안전장치로 유지
2 신규 번호 미리보기 팝업 열 때 번호 표시 저장 시 채번 미리보기 또는 안내문. 채번 자체는 서버 유지
3 배송현황 있음 있음(문서), 라이브 없음 추가
4 PPAP 서류 6대 18대 업무 확정 후 한쪽으로 통일
5 시양산 12~24H 12H 업무 확정 후 통일
6 4대 금형비 재료/가공/관리·이윤/특수 가이드와 DDL이 다름 업무 확정 후 화면, DDL 동시 수정
7 허브 선택 있음 로그인 역할 분기 협력사 접속 방식 확정 후 결정
8 상세 팝업 성격 읽기·판정 카드 편집 폼과 툴바 판정 버튼(승인·반려)이 있는 화면은 카드형으로 맞추는 것을 권장

9. 미확인 항목과 다음 확인 계획

  1. 저장·삭제·판정 동작: 모든 저장, 삭제, 승인 버튼은 누르지 않았다. 데이터를 바꾸므로 시험용 데이터로 허락받은 뒤 확인해야 한다. 특히 "PROC_… 저장 시 채번과 보완", "PPAP 승인 후 PO 생성", "빈 폼으로 열린 팝업에서 프로젝트를 고르면 값이 채워지는지"가 확인 대상이다.
  2. 빈 폼 팝업의 원인: 선택 행을 팝업이 넘겨받지 못하는 것인지, 팝업 안에서 프로젝트를 고르면 채워지는 의도된 동작인지. 6개 팝업 모두 "프로젝트 번호" 선택 상자가 있어 후자일 가능성도 있다. 이 경우 설계(선택 행 기준)와 다른 UX다.
  3. 팝업 안쪽 스크롤 영역: C210000 상세/심의, C240000 금형제작 승인서, C220000 제품검토 승인 아래쪽(Step 4 발주서 영역).
  4. 미수령 파일: arcforge-manifest.json(메뉴 트리), openapi-spec.json, sync-service.ts. 매니페스트를 보면 배송현황이 의도적으로 빠졌는지 알 수 있다.
  5. 라이브 DDL: 112개 테이블 기준 DDL이나 정보 스키마 내보내기가 있으면 화면 필드와 컬럼을 1:1로 연결할 수 있다.
  6. 시스템관리 하위 메뉴, 기준정보 화면, 협력사·관리자 계정 화면

10. 설계 목업 쪽 정정 사항

설계 명세(user-manual-v2)에서 아래 동작은 이상 동작으로 표시돼 있다. 컨버전에 그대로 따라 만들지 않는다.

  • 기존 번호 연동에서 프로젝트를 바꿔도 견적번호와 원청 고객사가 이전 값으로 남는 문제. 가이드 규칙은 견적 차수를 올리는 것이다(8.4절).
  • 신규 모드로 되돌릴 때 프로젝트명과 제품명이 남는 문제.
  • 원청사 견적 등록에서 LH/RH 두 행의 품번이 같게 채워지는 문제.
  • 신규 번호 예시(MI26006P0에 Q26001-01)가 가이드 채번 규칙과 맞지 않는 문제.
